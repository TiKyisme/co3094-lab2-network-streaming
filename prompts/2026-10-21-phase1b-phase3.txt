## 3. PRIORITY TASK — WINDOWS TO UBUNTU HTTP SERVER

Mục tiêu kỹ thuật quan trọng nhất:

Máy Windows vật lý truy cập thành công HTTP Server chạy trên máy ảo Ubuntu VirtualBox.

### Stage A — Source Verification

Tìm đúng:

- `server.py` do thầy cung cấp.
- Phiên bản `new_connection` được thầy overwritten trong forum `Lab 1 - Network device and Network application`.
- Cấu hình host, port và luồng xử lý HTTP request/response.

Nếu các file đó chưa có, hãy xác định rõ đang thiếu gì và yêu cầu tôi cung cấp. Không được tự nhận bản HTTP Server minh họa là bản chính thức.

Có thể chuẩn bị công cụ kiểm thử độc lập, nhưng phải phân loại là `DEMO_ONLY`.

### Stage B — Environment Discovery

Kiểm tra thực tế:

- Windows version.
- Python installation.
- VirtualBox installation.
- Ubuntu VM.
- VirtualBox networking modes.
- Host IPv4.
- Guest IPv4.
- Guest firewall.
- Server listening address và port.

Lưu ý: `VBoxManage` không nằm trong PATH không đồng nghĩa VirtualBox chưa được cài. Kiểm tra cả vị trí cài đặt thông thường và GUI.

### Stage C — Guided Execution

Hướng dẫn tôi từng bước và chờ output thật khi cần thao tác thủ công.

Ưu tiên topology Host-only cho kết nối host ↔ guest; thêm NAT nếu Ubuntu cần Internet.

Các kiểm tra cần thực hiện:

- Ubuntu: `ip -4 addr`
- Ubuntu: `ss -lntp`
- Windows: `ipconfig`
- Windows: `Test-NetConnection <VM_IP> -Port <PORT>`
- Windows: `curl.exe -v http://<VM_IP>:<PORT>/`
- Trình duyệt Windows truy cập HTTP Server trên Ubuntu.

Phân biệt:

- TCP connectivity success.
- HTTP response success.
- Browser rendering success.

Không coi một bài test là PASS nếu chưa thấy kết quả.

### Stage D — Evidence

Sau khi tôi chạy test:

- Phân tích terminal output.
- Xác nhận HTTP status/response.
- Kiểm tra server log.
- Hướng dẫn lưu screenshot thật.
- Ghi rõ cấu hình mạng đã được kiểm thử.
- Cập nhật kết quả trong repo.

Nếu chưa test được, giữ trạng thái `WAITING_FOR_MANUAL_TEST`.
